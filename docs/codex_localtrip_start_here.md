# LocalTrip — Codex 开发启动说明

这是交接指令，不是已完成项目。配合 `travel_booking_project_plan_v1.md` 使用。先将计划放入仓库 `docs/project-plan.md`。

## 任务

建立一个单家新西兰旅游活动运营商的响应式 Web 预约系统。近期仅实施 V1：活动、场次、预约/取消、商家后台、权限、测试和部署。所有内容是演示，不收真钱。

## 已确定技术方向

Next.js App Router、TypeScript、Tailwind CSS、shadcn/ui、Zod、PostgreSQL、Prisma、Supabase Auth、Vitest、Playwright。

初始化时核对当前稳定版本与兼容要求，锁定版本，不直接复制过时脚手架。身份来自服务端验证过的会话；业务表由服务端 Prisma 访问。Supabase Auth 管理认证；业务角色从 app_users 读取，不能来自用户可编辑字段。只用 Prisma 访问业务表时关闭不需要的 Supabase Data API。

## 后续必须遵守的核心规则

- PostgreSQL 是库存最终来源；每个会改容量的流程走同一业务服务。
- 锁顺序遵守计划：需要活动状态锁时先活动，再场次，再预约；不反向加锁，事务中不调用外部服务。
- 同一幂等键只对应一个提交意图；唯一约束冲突必须完整回滚。
- 取消只能释放一次名额；关闭销售不等于取消已有预约。
- 价格由服务端确定并记录快照；时间使用绝对时间与 Pacific/Auckland 显示。
- 游客只能读取自己的预约；工作人员权限每个端点都验证。
- 不把前端按钮隐藏当权限，不把假数据测试称为 PostgreSQL 并发测试。
- 不执行生产重置、擅自删数据、公开 STAFF 密码或记录秘密。
- 不生成真实付款、不自动发送真实客户邮件、不创建付费资源。
- 让用户能够理解并解释关键代码；修改后附小段说明及验收方法。
